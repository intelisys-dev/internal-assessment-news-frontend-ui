# News Frontend UI

## Scenario

Complete a frontend-focused implementation that allows a user to search for news
articles. Create a modern and visually impressive tool that showcases your
skills and knowledge in frontend development.

Some of the requirements require decisions about what good UX behavior is. Your
submission will be graded on the best practices and UX decisions you make, as
well as how those decisions shape the application architecture.

Prioritize the aspects that you would normally prioritize while working on a
professional development team and the habits you would bring to day-to-day
delivery.

## Prerequisites

Register for a free [NewsAPI API Key](https://newsapi.org/register) for use as
a data source within your project submission.

## Timebox

Plan for about **4 hours** of focused work. Prefer a solid, incomplete solution
over a shallow pass at everything. Prioritize what you believe matters most,
and document what you would finish next.

## Requirements

1. Retrieve news data from [NewsAPI](https://newsapi.org/docs) using the API key
   you obtained above.
2. Include a text input for searching articles by keyword.
   - Consider search UX beyond a bare text box.
   - Search should behave well under real use, including imperfect network
     conditions.
3. Display results with the article image, title, and description.
4. Provide a Read more path to the full article.
   - Warn the user before leaving for a different host, and let them confirm.
   - Consider standard browser / link behavior.
5. Support sorting results.

## Bonus features

If time allows, feel free to consider these ideas to implement:

1. Let the user mark a news source as favourite.
2. Track sources/articles already visited.

## Parameters

- Do not implement login / user management.
- No backend service is required for this assessment.
- You may use any boilerplate or starter app to bootstrap.
- Modern React is expected.

## Delivery timeline

- We expect you will need at most **4 hours** to complete this assessment.
- When provided you will be given a preferred delivery date.
- Missing that date is acceptable but will be taken into consideration.
- Spend more or less time as you judge appropriate.
- If you are not finished after one week, submit what you have.

## AI agent policy

- AI use in the submission is expected.
- Be prepared to explain your approach or thought process for the code you submit.

## Submission

Submit a **public GitHub repository** and email the link to the contact who
sent this assessment. The repo should include:

- All files needed to run the project
- A README with build and run instructions

## Interview

If you are selected for a follow-up interview, you must be ready to **share your
screen** and **walk through your submission’s code** (structure, decisions, and
trade-offs). Expect questions about how the app behaves and why you built it the
way you did.
